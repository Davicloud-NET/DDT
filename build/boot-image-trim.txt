# What Build-BootImage.ps1 removes from boot.wim, which a PXE netboot fetches over TFTP, so every megabyte here
# is time at every netboot. -SkipTrim keeps everything.
#
# A line is a path in the image from its root. * stands for any characters within one name, and a path takes
# everything below it. A line that starts with ! keeps what it matches. Most files in Windows PE have a second
# name, their copy in a WinSxS component folder. A file leaves the image only when all its names are removed or
# are such copies. A file that a kept folder shares, such as System32\locale.nls, which SysWOW64 links to,
# stays, and only the removed name goes.
#
# Every group was tried on its own and all of them together, on the ADK 10.1.26100.2454 image with the
# PowerShell components, the agent and the console. That image booted, partitioned a disk, and ran cmd,
# PowerShell 5.1, CIM, Get-Disk, ConvertTo-Json, [xml], Add-Type, HttpUtility and dism.exe. The sizes are
# what each group saved alone, in megabytes of 1,048,576 bytes of boot.wim. They overlap, so together they took
# boot.wim from 486 MB to 305 MB, 181 MB less, not their sum.

# 32-bit Windows, 67 MB. The ADK's Windows PE has no WOW64 layer: wow64.dll, wow64cpu.dll and wow64win.dll
# are not in it, so no 32-bit program can start, and nothing ever reads SysWOW64. Windows still maps
# SysWOW64\ntdll.dll while it starts, so that one file stays.
\Windows\SysWOW64
\Windows\WinSxS\x86_*
\Windows\WinSxS\wow64_*
\Windows\Microsoft.NET\Framework
\Windows\Microsoft.NET\assembly\GAC_32
\Windows\assembly\GAC_32
\Windows\assembly\NativeImages_v4.0.30319_32
!\Windows\SysWOW64\ntdll.dll

# Precompiled .NET Framework assemblies, 30 MB. PowerShell compiles the assemblies it loads as it loads them,
# which makes its first command in a run take a second or two longer.
\Windows\assembly\NativeImages_*
\Windows\Microsoft.NET\Framework64\v4.0.30319\NativeImages

# PE loads.
